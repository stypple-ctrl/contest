# 제작 기록: 검색 서비스가 신뢰할 수 있는 학습 재료가 되기까지

이 문서는 공개 전 별도로 보존한 개발 기록과 현재 코드·문서를 바탕으로, 무엇을 만들었고 어떤 문제를 고쳤는지 정리한 기록이다. 회고는 확인 가능한 변화에 한정한다. 따라서 당시의 모든 의사결정이나 작업 시간을 재현하는 일지는 아니다.

## 출발점: 공모전 검색의 최소 기능

2026년 6월 말의 첫 구현은 초·중·고 학생이 참가할 수 있는 공모전을 검색하는 서비스와 SQLite 데이터, 수집·정규화·검수 절차를 함께 추가했다. 여기서 중요한 선택은 화면부터 만들지 않고, **원시 정보 → 표준 레코드 → 검수 → 검색**이라는 데이터 경로를 먼저 둔 점이다.

초기 설계가 남긴 교훈은 간단하다. 검색 화면은 보기 좋게 만들 수 있지만, 참가 대상과 마감일이 틀리면 사용자에게 실질적인 도움이 되지 않는다. 그래서 원문 출처와 표준화된 값을 함께 보존하는 구조가 이후 개선의 기준이 되었다.

## 6월 28~29일: 화면과 데이터의 불일치를 줄이기

초기 공개 직후 이어진 커밋은 검색 경험의 작은 마찰을 줄이는 데 집중했다.

- 검색 필터의 모양과 동작을 정리했다.
- 결과 카드와 공모전·문화행사 화면의 이동 방식을 맞췄다.
- 문화행사 학년 필터의 오류를 수정했다.
- 저장 기능과 블로그 초안 흐름을 눈에 보이게 하고 일관되게 만들었다.

이 변화는 “공통 UI를 한 번에 완성”한 사례라기보다, 실제 화면에서 드러난 불일치를 커밋 단위로 좁혀 간 사례다. 다른 주제의 검색 서비스에서도 필터, 카드, 상세 화면의 규칙을 따로 만들면 사용자는 같은 서비스 안에서 서로 다른 조작법을 배워야 한다.

## 신뢰성 개선: 링크와 출처를 분리하다

제작 중 프런트엔드에서 API 키가 노출될 가능성을 제거하고 이를 점검하는 테스트를 추가했다. 비밀값을 브라우저 코드에 넣지 않는 것은 기능 개선이 아니라 공개 서비스의 전제다.

이후 여러 출처의 공모전 정보를 수집·정규화·교차 검증하는 스크립트를 추가했다. 현재 출처 정책도 같은 원칙을 따른다.

- `source_url`은 정보를 발견한 집계 사이트 링크로, 내부 감사와 대조에 쓴다.
- `official_url`은 기관·주최측의 원본 공고 또는 접수 링크로, 사용자에게 표시한다.
- 원본 링크가 없거나 검증이 충분하지 않은 항목은 확정된 정보처럼 보이지 않도록 conflict 상태로 남긴다.

여기서 얻은 교훈은 “링크가 있다”와 “신청에 쓸 수 있는 원본 링크다”를 구분해야 한다는 것이다. 특히 집계 사이트 데이터를 서비스에 다시 보여 줄 때는 원문을 복사하지 않고 사실을 재구성하며, 출처 조건과 검증 결과를 함께 다뤄야 한다.

## 문화행사 확장과 운영 자동화

다음 단계에서는 문화 API 갱신과 박물관 수집기, 주간 갱신 흐름 및 GitHub Actions 워크플로를 추가했다. 데이터가 시간이 지나면 낡는 서비스에서는 “한 번 수집”보다 “어떻게 다시 갱신할지”가 제품의 일부가 된다.

다만 자동화는 API 키와 외부 서비스 상태에 의존한다. 현재 `scripts/weekly_refresh.py`는 필요한 환경변수가 없으면 해당 수집 단계를 건너뛰도록 되어 있다. 즉, 자동 갱신은 편의 기능일 뿐 데이터 정확성을 보장하는 대체물이 아니다. 실행 결과와 검수 상태는 별도로 확인해야 한다.

## 현재 시점의 한계

이 저장소는 완성된 정답이 아니라 학습용 사례다. 특히 다음 한계는 의식적으로 남겨 두어야 한다.

- 외부 공고와 행사 정보는 수시로 변한다. 데이터 스냅샷은 최신 사실을 보장하지 않는다.
- 원본 URL이 있어도 접속 가능성·내용 일치 여부를 지속적으로 확인해야 한다.
- 수집 사이트의 robots 정책·이용약관·데이터 권리는 코드가 대신 판단할 수 없다.
- 자동 수집은 키, API 응답, 네트워크, 배포 비밀값에 의존한다.

## 다음 프로젝트에 가져갈 체크리스트

1. 검색에 쓰일 핵심 필드와 원문 보존 규칙을 화면보다 먼저 정한다.
2. 사용자용 원본 링크와 내부 수집 출처를 분리한다.
3. 모호한 값은 억지로 확정하지 말고 검수 대상으로 표시한다.
4. 외부 API·날짜·환경변수는 실패 경로까지 시험한다.
5. 자동화 뒤에도 결과 수와 충돌·누락을 사람이 읽을 수 있는 보고서로 남긴다.
