# 보안·개인정보·외부 데이터 정책

이 문서는 이 저장소를 실행·공개·갱신할 때 지킬 최소 기준이다. 코드와 문서에 나타난 현재 구조를 설명하며, 외부 서비스의 약관이나 법률 자문을 대체하지 않는다.

## 비밀정보

문화행사 갱신 스크립트는 `KOPIS_API_KEY`, `CULTUREINFO_API_KEY`, `KCISA_MUSEUM_API_KEY`, `KCISA_MUSEUM_API_URL` 환경변수를 사용할 수 있다. 값 자체는 저장소에 넣지 않는다. `.env.example`에는 이름만 두고, 실제 값은 로컬 환경변수 또는 배포 플랫폼의 비밀 저장소에 둔다.

- 브라우저에서 실행되는 `web/` 코드에는 API 키를 넣지 않는다.
- 로그·스크린샷·이슈·문서에 비밀값을 복사하지 않는다.
- 실제 키가 현재 파일이나 Git 이력에 있었다면, 파일을 지우는 것만으로 충분하지 않다. 발급처에서 즉시 폐기·재발급한다.
- GitHub Actions에는 저장소 비밀값을 사용하고, 실행 로그에 값을 출력하지 않는다.
- API 요청 URL을 DB나 로그에 보관할 때는 `scripts/culture_env.py`의 `sanitize_url`처럼 인증 쿼리 파라미터를 먼저 제거한다.
- SQLite에서 민감값을 UPDATE 또는 DELETE한 뒤에는 `VACUUM` 또는 새 DB 재생성으로 파일 내부의 이전 바이트까지 제거하고 원시 파일을 다시 검사한다.

## 개인정보와 Git 이력

공개 전 검사는 현재 파일만 보면 부족하다. 삭제한 파일과 이전 커밋에도 이메일, 절대 경로, 토큰 조각, 내부 시스템 이름이 남을 수 있다.

검사 범위에는 다음을 포함한다.

- 추적 중인 코드·문서·설정·생성 데이터
- 전체 Git 이력과 커밋 작성자 메타데이터
- SQLite의 텍스트 컬럼과 내보낸 정적 데이터
- 이미지와 문서의 메타데이터
- 미추적·무시 파일은 **내용을 공개하지 않고 경로와 공개 필요성만** 확인

개인 참가자 정보, 개인 전화번호, 개인 이메일, 인증정보는 학습과 검색에 필요하지 않으므로 공개하지 않는다. 기관이 공고에 공개한 연락처라도, 서비스에 다시 표시할 필요가 있는지 따로 판단한다.

## 출처·링크·저작권

이 서비스는 집계 사이트를 후보 발견 경로로 사용할 수 있지만, 사용자에게 제공하는 “원본 공고”는 가능한 한 기관 또는 주최측의 원본 공고·접수 페이지여야 한다.

| 값 | 용도 | 공개 원칙 |
|---|---|---|
| `source_url` | 발견 경로와 내부 감사·교차검증 | 사용자용 원본 공고 버튼에 사용하지 않음 |
| `official_url` | 기관·주최측 원본 공고 또는 접수 페이지 | 검증 가능한 경우 사용자에게 제공 |
| 원문 설명·포스터·로고 | 사실 확인과 출처 연결 | 원문 전체를 복제하지 않으며 각 권리자 조건을 따름 |

수집 단계에서는 제목·대상·일정 등 사실을 원문으로 보존할 수 있으나, 공개 설명은 사실을 바탕으로 자체 문장으로 재구성한다. robots.txt, 이용약관, 요청 간격, API 이용조건은 출처마다 확인한다. 접근이 막히거나 위반 소지가 있으면 수집을 멈추고 범위를 다시 결정한다.

## 데이터 품질과 안전한 표시

검증은 단순히 빈 칸을 찾는 작업이 아니다. 참가 자격, 마감일, 지역을 원본과 대조하고 날짜 순서와 중복을 확인한다. 확인할 수 없는 항목은 삭제로 감추기보다 `conflict` 또는 보류 상태로 남기고 사유를 기록한다.

웹에 내보낼 때에는 다음을 지킨다.

- 마감·종료된 항목의 표시 정책을 데이터 생성과 UI에서 일관되게 적용한다.
- 원본 URL이 없거나 집계 사이트 URL인 경우 “공식 링크”인 것처럼 표시하지 않는다.
- 외부 링크는 시간이 지나면 끊어질 수 있으므로 재확인 과정이 필요하다.
- 데이터 스냅샷의 기준 날짜와 갱신 한계를 이용자에게 알린다.

## 공개 전 최소 점검

1. 비밀값·개인정보·절대 경로를 현재 파일과 전체 Git 이력에서 검사한다.
2. 발견한 실제 비밀값은 회전한다.
3. API 키 없이도 웹앱이 기존 정적 데이터로 실행되는지 확인한다.
4. 키가 필요한 수집 기능은 키가 없을 때 안전하게 건너뛰거나 명확히 실패하는지 확인한다.
5. 외부 데이터·이미지·상표의 이용조건과 코드 라이선스를 분리해 고지한다.
