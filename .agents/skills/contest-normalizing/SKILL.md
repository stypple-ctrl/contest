# Contest Normalizing — 재가공/정규화 절차

normalizer 에이전트가 사용한다. 목표: 원시 데이터를 학원장이 검색 가능한 **표준 레코드**로 변환한다.

> 작업 전 반드시 `references/record-schema.md`(표준 레코드 전체 정의 + 분류 규칙)를 읽는다. 이 스킬은 절차, schema 파일은 규칙의 출처다.

## 왜 이 단계가 서비스의 핵심인가
학원장은 "초등 / 우리 지역 / 마감 안 지난 것"으로 검색한다. 이 세 축(참가연령·지역·마감일)이 부정확하면 서비스 전체가 쓸모없어진다. 그래서 정규화는 하네스에서 가장 중요한 부가가치 단계다.

## 절차
1. **입력 로드** — `_workspace/01_collector_*_raw.json`.
2. **대상 적격 판정** — 대학생/일반인 전용(초중고 불가)은 드롭하고 사유를 report에 기록. (규칙: record-schema의 참가연령 표)
3. **참가연령 분류** — `target_grade_detail`(원문) 보존 + `target_grades` 다중 태깅. 모호하면 `conflict`.
4. **지역 정규화** — 17개 시도/전국/온라인 표준값으로 변환, 원문은 `region_detail`.
5. **날짜 파싱** — 접수시작/마감, 행사 시작/종료를 `YYYY-MM-DD`로. 변환 불가 시 `null` + note.
6. **분야·유형 분류** — record-schema의 category/activity_type 값으로 매핑.
7. **요약 재구성** — 사실만 추출해 2~3줄 `summary`를 **자체 문장으로** 작성(복붙 금지).
8. **status 산출** — record-schema의 status 규칙 적용(오늘 날짜 기준).
9. **저장** — `_workspace/02_normalizer_records.json` + 결정/모호/제외 내역을 `02_normalizer_report.md`.

## 결정 원칙 (Why)
- **모호하면 단정하지 말고 conflict로 넘긴다.** 잘못된 자동 분류보다, 검수가에게 판단을 넘기는 편이 안전하다.
- **삭제보다 보존.** 제외할 때도 원문과 사유를 남겨 나중에 추적 가능하게 한다.
- **원문 필드 보존.** `*_detail` 필드에 원문을 남겨 검수가가 대조할 수 있게 한다.

## 반복 코드 번들링
날짜 파싱·지역 매핑·등급 매핑은 매번 동일하므로 결정적 헬퍼로 만들 수 있다(예: `scripts/normalize_helpers.py`의 `parse_date`, `map_region`, `classify_grade`). 동일 로직이 반복되면 스크립트로 추출해 재사용한다.
